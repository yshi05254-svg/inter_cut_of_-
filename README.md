# B站评论时间轴自动切片投稿

在B站视频下用自己的账号留一条带时间轴的评论，例如 `（1:14:40-2:14:40）`，程序会：

1. 找到该账号**最新一条**带时间轴的评论，以及它所在的视频；
2. 用该账号的登录状态，以账号能看的**最高清晰度**（大会员可到 4K / 1080P+）下载这段时间的片段；
3. 用指定的投稿账号**直接上传到B站**。没填标题时，默认标题为 `原视频名 时间轴`；
4. 按 `config.json` 里的任务列表**逐条**处理；
5. 可以完全在后台运行，只有扫码登录这一步需要人工操作（有现成脚本）。

## 安装

需要 Python 3.9+ 和 [ffmpeg](https://ffmpeg.org/download.html)（ffmpeg 要在 PATH 里，或者在配置里写「ffmpeg路径」）。

```bash
# Linux / macOS
scripts/install.sh
# Windows：双击 scripts\install.bat
```

或者手动安装：`pip install -r requirements.txt`，再把 `config.example.json` 复制为 `config.json`。

## 配置 config.json

```json
{
  "全局设置": { "轮询间隔秒": 600, "上传后删除本地文件": true },
  "任务列表": [
    {
      "投稿视频名": "",
      "tag": "切片,直播回放",
      "投稿账号": "13800000000",
      "投稿账号密码": "你的密码"
    }
  ]
}
```

每条任务的字段：

| 字段 | 必填 | 说明 |
|---|---|---|
| `投稿账号` | 是 | 用来投稿的B站账号（手机号/邮箱/用户名） |
| `投稿账号密码` | 否 | 用于后台自动登录；不填则只能扫码登录 |
| `投稿视频名` | 否 | 为空时用 `原视频名 时间轴`。可用占位符：`{原标题}` `{时间轴}` `{开始}` `{结束}` `{BV}` `{分P}` `{分P标题}` `{UP主}` |
| `tag` | 否 | 逗号分隔的字符串或数组，最多 10 个，为空时用「切片」 |
| `监听账号` / `监听账号密码` | 否 | 发评论的账号。不填就是投稿账号本身。下载清晰度按这个账号的权限 |
| `简介` | 否 | 支持同样的占位符；为空时自动写原视频链接和时间轴 |
| `分区tid` | 否 | 投稿分区，不填则沿用原视频分区 |
| `自制` | 否 | 默认 `false`，按「转载」投稿并附上原视频链接 |
| `指定视频` | 否 | 额外要扫描评论的视频（BV号或链接）列表 |
| `任务ID` | 否 | 用来区分记录；同一组账号配了多条任务时请填写 |
| `启用` | 否 | `false` 时跳过该任务 |

全局设置（都可以不写，以下为默认值）：

| 字段 | 默认 | 说明 |
|---|---|---|
| `轮询间隔秒` | 600 | `--loop` 模式下每轮间隔 |
| `扫描历史视频数` | 20 | 在监听账号最近看过的多少个视频里找评论 |
| `每视频扫描评论页数` | 3 | 每页 20 条，按时间倒序 |
| `精确剪切` | false | `true` 时在切点重新编码，起止时间精确到帧，但更慢；`false` 时切点会对齐到最近的关键帧（误差通常 1~5 秒） |
| `上传后删除本地文件` | false | |
| `默认分区tid` | 21 | 拿不到原视频分区时使用 |
| `上传线路` | bda2 | upos 线路，可选 `bda2`/`tx`/`txa`/`alia`/`bldsa`，填空字符串让B站自动分配 |
| `下载格式` | `bv*+ba/b` | yt-dlp 的 `-f` 参数 |
| `yt-dlp额外参数` | [] | 例如 `["--limit-rate", "5M"]` |
| `最大重试次数` | 3 | 同一条评论处理失败这么多次后放弃 |
| `请求间隔秒` | 0.6 | 调大可降低被风控（412）的概率 |

评论里的时间轴支持这些写法：`(1:14:40-2:14:40)`、`（1:14:40-2:14:40）`、`14:40~20:05`、`1：02：03 到 1：05：00`、`【0:10—0:30】`。多P视频可以写 `P2 1:00-2:00`，不写P时用你在历史记录里看的那一P。

## 使用

```bash
python main.py login        # 首次使用：登录 config 里的所有账号
python main.py check        # 查看账号登录状态、是否大会员
python main.py run          # 处理一遍
python main.py run --loop   # 常驻，每隔「轮询间隔秒」处理一遍
```

### 登录方式（哪些能在后台完成）

1. **缓存凭据**：登录成功后 cookie 保存在 `data/accounts/`，后续运行直接复用，完全在后台。
2. **密码登录**：缓存失效时，用 config 里的密码走客户端接口自动登录，也在后台完成。B站对新设备、异地登录可能要求安全验证，这时密码登录会失败。
3. **扫码登录**：前两种都不行时，需要运行 `scripts/login.sh`（Windows 用 `scripts\login.bat`）。终端会显示二维码（同时保存为 `data/accounts/<账号>_qrcode.png`），用B站 App 扫码确认即可。也可以用 `python main.py login 账号 --qrcode` 直接扫码。

在后台模式（`--daemon`）下程序从不等待扫码：遇到需要登录的账号会跳过该任务、写日志，其它任务照常执行。

### 后台运行

| 方式 | 命令 |
|---|---|
| Linux/macOS 常驻 | `scripts/start.sh`，停止用 `scripts/stop.sh` |
| crontab 定时 | `*/10 * * * * /项目路径/scripts/run_once.sh` |
| systemd | 修改 `scripts/bili-clipper.service` 里的路径后 `systemctl enable --now bili-clipper` |
| Windows 常驻（无窗口） | 双击 `scripts\start_background.bat` |
| Windows 定时 | 在「任务计划程序」里定时运行 `scripts\run_once.bat` |

日志保存在 `data/logs/clipper.log`，已处理的评论记录在 `data/state.json`。程序带运行锁，定时任务重叠时会自动跳过。

## 工作原理与限制

- **怎么找到「最新一条评论」**：B站没有公开的「某个用户发过的所有评论」接口，所以程序在监听账号**最近观看的视频**（历史记录）和「指定视频」里，按时间倒序翻评论，找出这个账号发的、含时间轴的最新一条。因此：
  - 监听账号**不能关闭观看历史**；评论的视频要在最近 `扫描历史视频数` 个视频以内；
  - 只识别**一级评论**，楼中楼回复识别不到；
  - 评论很多的热门视频，如果你的评论之后又有超过 `每视频扫描评论页数 × 20` 条新评论，可能会翻不到；可以调大页数，或把视频写进「指定视频」。
- **只处理最新的一条**：每轮只投稿最新一条带时间轴的评论；处理成功后，比它更早的评论不会再处理。同一条评论不会重复投稿。
- **下载**用 [yt-dlp](https://github.com/yt-dlp/yt-dlp) 加监听账号的 cookie，只下载需要的时间段，不下载整个视频。
- **投稿**走B站网页端接口：分片上传到 upos，重新上传原视频封面，默认以「转载」提交并附原视频链接。新账号、等级低的账号投稿可能触发验证码或被限制，这时需要在网页上手动投稿一次。
- `config.json` 里是明文密码，`data/accounts/` 里是登录凭据，请妥善保管（已写入 `.gitignore`）。
- 转载他人视频请遵守B站社区规范和原作者的授权要求。

## 测试

```bash
pip install pytest
python -m pytest tests
```

`tests/test_flow.py` 用模拟的B站接口跑通「找评论 → 下载 → 分片上传 → 投稿」的完整流程。
